# Plan: Fix Bugs in ImageBlock Component (BlockEditor)

## Context

The ImageBlock component in the BlockEditor has several bugs affecting user experience, particularly:

1. **Primary Bug**: Clicking "add image" causes the media library dialog to disappear and the block loses focus
2. **Secondary Bugs**: Event handling issues, state management problems, focus management failures, dialog interaction conflicts, and potential race conditions in useEffect/useCallback

## Bug Analysis (From Codebase Exploration)

### 1. Primary Bug: Media Library Disappears and Focus Loss on "Add Image" Click

**Root Causes:**
- **Focus Loss on Dialog Open**: Radix UI Dialog is modal and traps focus, causing editor focus loss → block selection cleared → `isSelected = false`
- **No Focus Restoration on Dialog Open**: Unlike `handleMediaSelect` (which restores focus after dialog close), no restoration happens when dialogs open
- **Potential Dialog Closure Triggers**: Large MediaDialog size, async operations in MediaLibrary, conflicting sub-dialogs, or focus trapping failures
- **useEffect Dependency Issues**: Runs on `choiceDialogOpen` changes but doesn't handle selection loss during transitions
- **Race Conditions**: Batched state updates may not sync with selection state changes

**Code Flow Issue:**
1. Click "add image" → `setChoiceDialogOpen(true)` → dialog opens → focus shifts → selection lost
2. Click "Media library" → `setMediaDialogOpen(true)` → MediaDialog opens → potential closure due to size/layout issues → dialog disappears
3. No focus restoration logic for dialog opening (only closing)

### 2. Other Bugs Identified

**Event Handling:**
- Missing checks for dialog events in `handleSelect`
- Potential interference from `onPointerDownCapture` during transitions
- Silent failures in `captionRef.current?.focus()`

**State Management:**
- `autoOpenedRef` never reset, could prevent future auto-opens
- Dead code: `inputUrl` state and `handleUrlSubmit` unused
- `variantsJson` inconsistency: different formats for URL vs media selection
- Invalid `height = 0` can cause CLS issues

**Focus Management:**
- `scheduleBlockSelection` uses try/catch but ignores failures
- No cleanup for unexpected dialog closures
- `useBlockDragHandle` disabled but state may persist

**Dialog Interactions:**
- Multiple dialogs rendered simultaneously
- Potential z-index conflicts
- Missing explicit `modal` props on Dialog components
- Conflicting sub-dialogs in MediaLibrary

**useCallback/useEffect Issues:**
- Potential stale closures if `block`/`editor` change
- `useEffect` runs excessively on dialog state changes
- Missing cleanup on unmount

**Async Operations:**
- Block updates synchronous, focus restoration async
- Potential unmount/re-render before focus restores
- Editor state instability during transitions

## Fix Plan

### Phase 1: Fix Primary Bug (Focus Loss & Dialog Disappearance)

**1.1 Add Focus Restoration on Dialog Open**
- Modify `useEffect` to restore block selection when dialogs open
- Add `scheduleBlockSelection(block.id); selectBlock();` inside `useEffect` if a dialog opens and `isSelected` is false
- Remove `isSelected` condition from `useEffect` for auto-opening logic

**1.2 Stabilize Dialog Behavior**
- Ensure MediaDialog handles large sizes without layout issues
- Add error boundaries around MediaLibrary async operations
- Prevent conflicting sub-dialogs from closing parent dialog

**1.3 Improve Focus Management**
- Add explicit focus restoration in dialog open handlers
- Ensure `Dialog` components have proper `modal` and focus trapping settings
- Add cleanup for focus on unexpected dialog closures

### Phase 2: Fix Secondary Bugs

**2.1 State Management Fixes**
- Reset `autoOpenedRef` appropriately
- Remove dead code (`inputUrl`, `handleUrlSubmit`)
- Standardize `variantsJson` format across all handlers
- Validate `height` > 0 before setting

**2.2 Event Handling Improvements**
- Add dialog event filtering in `handleSelect`
- Improve pointer event handling during transitions
- Add error handling for `captionRef.focus()`

**2.3 Dialog Interaction Fixes**
- Prevent multiple dialogs from rendering simultaneously
- Fix z-index conflicts
- Add explicit modal props to Dialog components

**2.4 Hook Optimization**
- Review and fix useCallback dependencies
- Optimize useEffect to run less frequently
- Add proper cleanup in useEffect

### Phase 3: Testing & Validation

**3.1 Unit Tests**
- Test dialog opening/closing with focus preservation
- Test block selection maintenance during async operations
- Test state consistency across handlers

**3.2 Integration Tests**
- Test full "add image" flow: click → choice dialog → media library → selection
- Test focus behavior with keyboard navigation
- Test dialog stability with various content sizes

**3.3 Manual Testing**
- Verify no focus loss in various scenarios
- Test on different screen sizes (MediaDialog responsiveness)
- Test with slow network/async failures

## Risks

- **Over-engineering Focus Management**: Too much focus restoration could cause flickering or conflicts
- **Dialog Performance**: Adding error boundaries and checks might slow dialog opening
- **Breaking Changes**: State management changes could affect other BlockEditor features

## Success Criteria

- Clicking "add image" maintains block selection and keeps dialogs open
- No focus loss during dialog interactions
- All dialogs behave consistently and reliably
- No dead code or inconsistent state management
- Performance remains acceptable
- Block editing experience is smooth and predictable
