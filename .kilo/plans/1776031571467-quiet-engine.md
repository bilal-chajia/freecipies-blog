# Plan: Audit et correction de TOUS les champs cached du système

## Résumé

Audit complet de **22 champs cached/denormalisés** sur **4 tables** + 2 index FTS5. Résultat :
- **5 fonctionnent correctement** (SQL triggers ou sync fiable)
- **7 sont complètement cassés** (jamais peuplés)
- **4 partiellement fonctionnels** (se désynchronisent après modification d'entité source)
- **1 bug de schéma** (table `redirects` dupliquée)
- **3 cascades manquantes** (author/category/tag → articles)

## Problèmes détaillés

### CRITIQUE — Champs jamais peuplés (7)

| Champ | Table | Impact |
|-------|-------|--------|
| `cached_card_json` | articles | API `/api/content` ne peut pas utiliser ce cache → toujours fallback |
| `faqs_json` | articles | FAQ schema.org jamais généré, blocs FAQ pas agrégés |
| `jsonld_json` | articles | Données structurées SEO jamais générées |
| `reading_time_minutes` | articles | Toujours 0, cartes affichent un temps incorrect |
| `cached_post_count` | authors | Toujours 0, pas de tri par popularité auteur |
| `cached_post_count` | tags | Toujours 0, tag cloud non trié par popularité |
| `idx_media_search_fts` | media | Index FTS5 vide, recherche media utilise LIKE à la place |

### ÉLEVÉ — Données périmées / non nettoyées (4)

| Problème | Détail |
|----------|--------|
| Caches recette non vidés | Si `type !== 'recipe'`, `cachedRecipeJson`/`cachedEquipmentJson`/`totalTimeMinutes`/`difficultyLabel` gardent leurs anciennes valeurs |
| `cachedTocJson` non vidé | Si `contentJson` est vidé, le TOC reste (condition `toc.length > 0`) |
| `cachedRatingJson` pas reconstruit | Seulement mis à jour via `addRecipeVote()`, pas via `syncCachedFields()` |
| `cachedTagsJson` pas dans sync | Seulement reconstruit dans `setArticleTagsById()` |

### ÉLEVÉ — Cascades manquantes (3)

| Cascade manquante | Impact |
|-------------------|--------|
| Auteur modifié → articles | `cached_author_json` stale dans tous les articles de cet auteur |
| Catégorie modifiée → articles | `cached_category_json` stale dans tous les articles de cette catégorie |
| Tag renommé → articles | `cached_tags_json` stale dans tous les articles avec ce tag |

### MOYEN — Incohérences de schéma (2)

| Champ | Attendu (schema.sql) | Actuel |
|-------|---------------------|--------|
| `cached_category_json` | `{ id, slug, name, icon_svg }` | `{ label, slug, color }` — manque `id`, `name` vs `label` |
| `cached_author_json` | `{ id, slug, name, job_title, avatar: { url, alt } }` | `{ name, slug, avatar: string, role }` — manque `id`, avatar est string |

  "shortDescription": "Flaky buttery biscuits...",
  "thumbnail": {

    "variants": {
      "xs": { "url": "...", "width": 360, "height": 240 },

  },
  "category": { "slug": "desserts", "name": "Desserts", "color": "#ff6600ff" },
  "author": { "slug": "jane-doe", "name": "Jane Doe", "avatarUrl": "..." },

### Structure corrigée pour `cachedCategoryJson`

```jsonc

```

### Structure corrigée pour `cachedAuthorJson`

```jsonc
{ "id": 5, "slug": "jane-doe", "name": "Jane Doe", "jobTitle": "Senior Editor", "avatar": { "url": "...", "alt": "Jane Doe" } }
```

### Pattern cascade — Réutiliser le modèle equipment

Le seul pattern cascade existant et fonctionnel est `refreshCachedEquipmentForArticles()`. Le reproduire pour :
- `refreshCachedAuthorForArticles(db, authorId)` — dans `authors.service.ts`
- `refreshCachedCategoryForArticles(db, categoryId)` — dans `categories.service.ts`
- `refreshCachedTagForArticles(db, tagId)` — dans `tags.service.ts`

## Plan d'implémentation

### Phase 1 : Corriger `syncCachedFields` (articles.service.ts)

**Fichier :** `src/modules/articles/services/articles.service.ts`

#### 1.1 Corriger le schéma `cachedCategoryJson`
- Ajouter `id`, renommer `label` → `name`, garder `color`, ajouter `iconSvg`
- Résultat : `{ id, slug, name, color, iconSvg }`

#### 1.2 Corriger le schéma `cachedAuthorJson`
- Ajouter `id`, convertir `avatar` string → `{ url, alt }`, renommer `role` → `jobTitle`
- Résultat : `{ id, slug, name, jobTitle, avatar: { url, alt } }`

#### 1.3 Ajouter reconstruction `cachedTagsJson` dans sync
- Réutiliser `getTagsForArticleId()` existant
- Écrire les labels dans `cachedTagsJson`

#### 1.4 Ajouter reconstruction `faqsJson`
- Scanner `contentJson` pour blocs `type === 'faq_section'`
- Agréger `items` → `[{"q": "...", "a": "..."}]`

#### 1.5 Calculer `readingTimeMinutes`
- Compter les mots de `contentJson` (paragraphs, headings, blockquotes, lists, tip_box)
- `Math.max(1, Math.ceil(wordCount / 200))`

#### 1.6 Reconstruire `cachedRatingJson`
- Si `recipeJson.aggregateRating.ratingCount > 0` → `{ ratingValue, ratingCount }`
- Sinon → `'{}'`

#### 1.7 Nettoyer caches recette pour non-recettes
- Si `type !== 'recipe'` ou `recipeJson` null :
  - `cachedRecipeJson` → `'{"isRecipe": false}'`
  - `cachedEquipmentJson` → `'[]'`
  - `cachedRatingJson` → `'{}'`
  - `totalTimeMinutes` → `null`
  - `difficultyLabel` → `null`

#### 1.8 Toujours écrire `cachedTocJson`
- Retirer la condition `if (toc.length > 0)`, toujours écrire (même `[]`)

#### 1.9 Générer `cachedCardJson`
- Champs communs : `headline`, `shortDescription`, `thumbnail`, `category`, `author`, `publishedAt`, `updatedAt`, `readingTimeMinutes`
- Recipe : `rating`, `totalTimeMinutes`, `difficulty`, `servings`, `caloriesPerServing`
- Roundup : `itemCount`
- Thumbnail : slot `thumbnail` puis fallback `cover`, limité xs/sm/md

#### 1.10 Générer `jsonldJson`
- `Recipe` si `type === 'recipe'`
- `FAQPage` si `faqsJson` non vide
- `Article` si `type === 'article'`
- `BreadcrumbList` pour tous

### Phase 2 : Ajouter cascades cross-table

#### 2.1 Cascade auteur → articles
**Fichier :** `src/modules/authors/services/authors.service.ts`
- Créer `refreshCachedAuthorForArticles(db, authorId)`
- Query articles WHERE `author_id = authorId`
- Pour chaque article, reconstruire `cached_author_json` + `cached_card_json`
- Appeler dans PUT `/api/authors/[slug]` et PUT `/api/admin/authors/[id]` (fire-and-forget)

#### 2.2 Cascade catégorie → articles
**Fichier :** `src/modules/categories/services/categories.service.ts`
- Créer `refreshCachedCategoryForArticles(db, categoryId)`
- Query articles WHERE `category_id = categoryId`
- Pour chaque article, reconstruire `cached_category_json` + `cached_card_json`
- Appeler dans PUT `/api/categories/[slug]` et PUT `/api/admin/categories/[id]` (fire-and-forget)

#### 2.3 Cascade tag → articles
**Fichier :** `src/modules/tags/services/tags.service.ts`
- Créer `refreshCachedTagForArticles(db, tagId)`
- Via `articles_to_tags` → articles
- Pour chaque article, reconstruire `cached_tags_json` + `cached_card_json`
- Appeler dans PUT `/api/tags/[slug]` et PUT `/api/admin/tags/[id]` (fire-and-forget)

### Phase 3 : Ajouter SQL triggers manquants

**Fichier :** `db/schema.sql`

#### 3.1 Triggers `authors.cached_post_count`
- AFTER INSERT/UPDATE/DELETE sur `articles` → recalculer pour `author_id`
- Même pattern que les triggers existants pour `categories.cached_post_count`

#### 3.2 Triggers `tags.cached_post_count`
- AFTER INSERT/UPDATE/DELETE sur `articles_to_tags` → recalculer pour chaque `tag_id`
- Après UPDATE de `is_online`/`deleted_at` sur `articles` → recalculer tous les tags de cet article

#### 3.3 Triggers FTS5 pour `idx_media_search_fts`
- `trg_media_search_ai` — AFTER INSERT on `media`
- `trg_media_search_au` — AFTER UPDATE on `media` (delete old + re-insert si pas soft-deleted)
- `trg_media_search_ad` — AFTER DELETE on `media`
- Même pattern que les triggers existants pour `idx_articles_search`

#### 3.4 Supprimer la table `redirects` dupliquée
- Supprimer la 2ème définition (lignes 2424-2442)

### Phase 4 : Ajuster hydration.ts

**Fichier :** `src/shared/utils/hydration.ts`

- `hydrateArticle` : gérer `cachedAuthorJson` avec avatar objet `{ url, alt }` (fallback string)
- `hydrateArticle` : gérer `cachedCategoryJson` avec `name` (fallback `label`)
- Garder les fallbacks pour rétrocompatibilité

### Phase 5 : Ajuster les consommateurs directs

- `src/components/RecipePreviewCard.astro` — Fallback `.label ?? .name` pour category
- `src/pages/api/content/index.ts` — Utiliser le nouveau `cachedCardJson`

### Phase 6 : Valider

- `pnpm build` — Vérifier l'absence d'erreurs TypeScript
- Cohérence des types Drizzle

## Risques et mitigations

| Risque | Mitigation |
|--------|------------|
| Cascades lourdes si beaucoup d'articles | Fire-and-forget (async), pattern déjà éprouvé pour equipment |
| Changement schéma casse le frontend | `hydrateArticle` a déjà des fallbacks multiples, ajouter `.label ?? .name` et `typeof avatar === 'string'` |
| FTS5 index stale après cascade | Les cascades UPDATE les articles → les triggers FTS5 se déclenchent automatiquement |
| Performance syncCachedFields | +1 query (tags), reste léger. Parsing JSON uniquement, pas de requêtes lourdes |
| Triggers SQL pour tags via junction table | Attention au nombre de recalculs → batch trigger plutôt que per-row |
