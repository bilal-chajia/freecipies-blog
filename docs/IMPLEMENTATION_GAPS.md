# Implementation Gaps

> **Last Updated:** 2026-05-17

This document tracks temporary mismatches between the current codebase and the official contracts.

The contract documents must describe the target canonical format only. Legacy names, current implementation gaps, and temporary normalizer behavior belong here.

Current local audit command:

```bash
pnpm run contract:audit:local
```

The audit is local-only and uses local D1. Use `--fail-on-violations` when a phase should be contract-clean.

## Content Blocks

- Local `articles.content_json` has been migrated to `ContentDocument v1`.
- Local body image snapshots have been moved out of `content_json` into `articles.images_json.content_images`; stored image blocks now keep only `image_ref`.
- Strict content document validation rejects editor-only block names and obsolete stored block names.
- BlockEditor adapters convert internal editor names to canonical stored block names on save.
- Legacy editor names are still allowed inside the editor framework only; they must not cross the storage/API boundary.
- Roundup JSON-LD is generated by the server save/cache sync flow from
  `roundup_json`; the admin no longer generates ItemList JSON-LD locally.

Mapping for compatibility-only normalizers:

| Legacy editor block | Canonical block | Compatibility rule |
| --- | --- | --- |
| `alert` | `tip_box` | Convert `props.type` to `variant`; content becomes `text`. |
| `customImage` | `image` | Store only `image_ref`; move the snapshot to `images_json.content_images`. |
| `faqSection` | `main_faq` + `faqs_json` | Store one placement marker in `content_json`; keep FAQ items in `faqs_json`. |
| `relatedContent` | `related_content` | Convert editor selection/settings to canonical related content payload. |
| `roundupList` | `main_roundup` + `roundup_json.items[]` | Store one placement marker in `content_json`; keep item data in `roundup_json`. |
| `mainRecipe` | `main_recipe` | Save only the marker block; never duplicate `recipe_json`. |

## Article JSON

- Local `recipe_json`, `roundup_json`, `cached_recipe_json`, and
  `cached_rating_json` have been migrated to contract `snake_case`.
- Local `seo_json` rows on `articles`, `authors`, and `categories` have been
  migrated to the contract `snake_case` shape.
- Local `faqs_json` rows have been migrated to the source object shape with
  `heading`, `intro`, and `items[]`.
- Local article relationship caches have been migrated: `cached_author_json`
  no longer stores `role`, `cached_category_json` includes `id`, and
  `cached_tags_json` stores tag snapshots instead of string labels.
- Local `cached_card_json` rows now use the contract card shape with `image`,
  `category`, `author`, `tags`, optional `recipe`, and optional `rating`.
- Local `cached_toc_json` rows now include `number`, `parent_id`, and
  `source_type`; roundup item TOC ids match rendered roundup item anchors.
- Article, author, and category save paths now normalize SEO admin payloads
  before storage; admin response/load helpers still read old camelCase keys as
  a migration guard.
- Article save/cache sync now preserves `faqs_json` as source content instead
  of regenerating it from `content_json`.
- New article save payloads normalize `recipe_json` and `roundup_json` before
  storage.
- `roundup_json` remains the structured roundup item source; `content_json` should store only the `main_roundup` placement marker.
- Legacy FAQ cache items using `q`/`a` normalize to `question`/`answer`.
- Legacy rating cache items using `ratingValue`/`ratingCount` normalize to `rating_value`/`rating_count`.
- Article body image snapshots use `images_json.content_images`; `content_json` keeps `image_ref` markers only.
- Public content image rendering resolves `content_json.image.image_ref`
  through `images_json.content_images`.
- Public FAQ rendering happens at the `main_faq` marker position.
- Public roundup rendering now reads resolved item snapshots directly from
  `roundup_json.items[]`; the old render-time `roundupArticles` lookup path has
  been removed.
- Cache sync clears `cached_toc_json` to `[]` when the current content has no
  TOC entries.
- Public `related_content` rendering now consumes canonical
  `items[].snapshot` card payloads and resolves stored `r2_key` image variants
  at render time.
- Related-content adapter preserves a block `id` when saving canonical blocks.

## Recipe JSON

- Local stored `recipe_json` rows now use canonical `snake_case` top-level
  recipe fields.
- Local stored `cached_recipe_json` rows now use canonical `snake_case` cache
  fields.
- Local stored `cached_rating_json` rows now use `rating_value` and
  `rating_count`.
- `schema.sql` defaults and shared cache types now match the canonical
  `cached_recipe_json` and `cached_rating_json` shapes.
- Article save and cache sync paths now write contract-shaped recipe and rating
  JSON.
- Public recipe render components and the recipe listing API now consume the
  normalized contract shape for recipe fields, rating, nutrition, and video.
- JSON-LD generation reads `recipe_json` in contract shape and only emits
  Schema.org camelCase keys at the final JSON-LD output boundary.
- Recipe steps now use `image_ref`; public rendering and JSON-LD resolve those
  references through `images_json.recipe_steps`.
- Local legacy equipment affiliate links without `equipment_id` were migrated
  into manual checklist items.
- Article create/update now resolves active catalog `equipment_id` rows at
  save time and copies render snapshots into `recipe_json.equipment[]`.

## Media JSON

- Legacy stored payloads contain `sizeBytes`; readers normalize to `size_bytes`.
- Legacy stored image slots contain `aspectRatio`; readers normalize to `aspect_ratio`.
- New media upload writes require a structured author credit snapshot; free-string `media.credit` is rejected.
- `/api/media/upload-variant` and `/api/media/confirm` now use contract `snake_case` JSON at the API boundary.
- Admin image selection keeps resolved `url` payloads only; article/category/author
  server transforms normalize snapshots to stored `r2_key` variants before DB
  writes.
- Local D1/R2 media image keys have been migrated to `media/images/{slug_base}-{variant}-{asset_id}.{ext}`.
- Current local audit shows `media` rows are clean for required variants, placeholder, caption, and author credit snapshots.
- Local `authors.images_json` has been migrated to structural avatar/hero
  snapshots: `avatar` uses `xs` + `sm`, `hero` uses `sm` + `md` + `lg`, and
  neither stores `url`, `caption`, or `credit`.
- Author save payloads normalize `images_json` before storage.
- Category image saves now strip contextual `caption`, `credit`, and
  `original` variants from category structural image slots.

## Categories And Tags

- Category Drizzle/API writes no longer expose `config_json`, because category
  page behavior belongs to global site settings and `db/schema.sql` has no
  `categories.config_json` column.
- Tag `style_json` writes now keep only design hints (`color`, `variant`) and
  no longer serialize icon/raw SVG compatibility keys.

## Table Maintenance

- `authors.cached_post_count` and `tags.cached_post_count` are denormalized; refresh is handled by app logic or SQL automation.
- `categories.cached_post_count` is maintained by SQL triggers, while rich article snapshots are application-managed.
- `idx_media_search` has been removed in favor of FTS5 for better search performance.

## Site Settings

- Local `toc_settings` has been migrated to the contract `snake_case` keys:
  `default_open`, `show_jump_button`, `accent_color`, and `max_depth`.
- The appearance settings API validates only the stored contract keys for
  TOC writes.
- The settings service still normalizes old camelCase TOC values on read as a
  migration guard, but new writes persist the contract shape.
- Public cached loaders now exist for `site_identity`, `seo_defaults`,
  `homepage_settings`, `organization_profile`, and `public_social_links`.
- Homepage metadata now reads `homepage_settings.seo` through the cached public
  settings loader.
- Footer brand/contact/social rendering now reads `site_identity`,
  `organization_profile`, and `public_social_links` instead of hardcoded public
  values.
- Image upload settings validation now rejects unknown stored keys, and upload
  endpoints read settings through the settings cache when available.
- Local `menu_header`, `menu_footer`, `menu_mobile`, and `menu_sidebar` rows
  have been migrated from legacy raw arrays to canonical menu documents with
  `location`, `is_enabled`, `fallback_to`, and ordered `items[]`.
- The menus service now writes canonical menu documents and keeps legacy array
  reads as a migration guard only.
- Public header navigation reads canonical menu items and resolves links from
  `target.href` instead of legacy `url`.
- The local contract audit now checks canonical `menu_*` settings.
- The admin menu editor files used by this flow have been moved to TS/TSX and
  now edit canonical `menu_header`, `menu_footer`, `menu_mobile`, and
  `menu_sidebar` documents directly.
- The admin menu editor writes link targets through `target.href`, mega columns
  through `columns[].items[]`, and featured content through `featured_items[]`.
